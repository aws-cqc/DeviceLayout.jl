# [Developer Guide](@id dev-index)

This section is for people changing DeviceLayout.jl itself.
If you want to *use* the package, start with [Getting Started](../how_to/get_started.md).
That said, we encourage users to become contributors, especially when they encounter
bugs or missing features.

- [Design Principles](@ref dev-principles): high-level guidelines for decisions around
  triage, roadmapping, and review.
- [Conventions](@ref dev-conventions): style guidelines and substantive conventions
  like writing coordinate–type generic code.
- [Contributing](@ref dev-contributing): setting up a checkout, running and writing tests,
  formatting, building docs, benchmarks, what a pull request includes, and what reviewers
  look for.
- [Versioning Policy](@ref dev-versioning): versioning and deprecation policy; what
  counts as a breaking change.
- [Maintainer Runbook](@ref dev-maintenance): the release procedure, CI, and recurring chores
  like dependency and Julia version updates.

This project has adopted the [Amazon Open Source Code of Conduct](https://aws.github.io/code-of-conduct).

## Where to ask

Open a [GitHub issue](https://github.com/aws-cqc/DeviceLayout.jl/issues) for bugs, feature
requests, and questions about how something works. Security concerns go to AWS Security as
described in CONTRIBUTING.md, not to the public tracker.
